# Math Quest: rules for working on this repo

A kids' math game (Cloudflare Worker + one self-contained web page). Progress saves in the browser and, optionally, to
accounts in Cloudflare KV. Read this before changing anything.

## Layout and build
- **Edit `src/`, never `worker.js`.** `worker.js` is generated by `npm run build` and is committed on purpose (so the
  game can also be pasted into the Cloudflare dashboard). CI fails if it is out of date: run `npm run build` and commit it.
- `src/client/index.html` (page shell), `src/client/styles.css`, `src/client/js/NN-name.js` (joined in filename order into one
  `<script>`; top-level `const`/`let` must be declared before use at load time, functions can be used anywhere).
- `src/shared/econ.js` is included in BOTH the browser script and the Worker. `src/server/NN-name.js` is the Worker.
- Client code is plain JS written normally. No template-literal escaping tricks. The build syntax-checks it and fails on errors.
- No dependencies, no external network requests, no fonts or scripts from other sites (the CSP forbids them).
- The service-worker cache name is derived from the build hash automatically. Never bump a version by hand.

## Commands
- `npm test` builds, lints, then runs every test (about 3 minutes). `npm run lint` checks the browser script and the Worker for calls to functions that do not exist and for page handlers with no function behind them (an earlier refactor silently deleted `hubStep`). `npm run check` verifies `worker.js` is current. `npm run sim` prints the gem economy.
- Run `npm test` before every commit. A change that touches what players see needs a test, not just a screenshot.
- In the cloud sandbox Playwright's Chromium is already installed; do not run `playwright install`.

## Reuse before writing (most important rule)
Search the codebase first. Never write a second copy of something that exists. Existing helpers:
- Dates: `dayKey(d?)`, `daysAgoKey(n)`, `lastDayKeys(count, skip)`. Do not hand-roll date strings.
- Modals: `showModal(id, before)` / `hideModal(id, after)`; give the overlay `data-close="fn"` (tap + Escape) or `data-esc="fn"` (Escape only, for game screens). No per-modal `…OnOverlay` functions.
- Rewards: `grantGems(n, message, big)` for any payout that celebrates. Costs/rewards/limits live ONLY in `ECON` (`src/shared/econ.js`).
  After changing a number there run `npm run sim`; the economy tests must pass.
- Questions: `makeMcq({op, problem, count})` + `fillOptButtons()` for every multiple-choice screen (tournament, duels, vault).
- Buddy gear: every accessory has a `slot` (head, face, neck, back, side, aura); positions come only from `GEAR_SLOTS` in `08b-buddy-gear.js` and are used by the battle screen, hub and trading card. Never add per-item pixel offsets in CSS. Armor is the corner badge. New gear needs no CSS.
- Text safety: `escHtml()` for anything a user typed or the server sent, before it goes into `innerHTML`.
- Saves: `saveState()` (never `localStorage` directly), `statDay()`/`recordStat()` for parent-report numbers, `addXpTo(id, n)` for buddy XP.
- Practice difficulty: which type and level the next problem uses is decided only in `07b-adaptive.js` (`pickNextProblem`, `recordAdaptive`, `typeShares`); numbers are in `ECON.adaptive`. Levels follow recent accuracy and speed per type, never the combo streak. Tournaments, duels and the vault use `makeMcq`, which ignores levels on purpose (fair for both players).
- Stakes: `stakeAllowed()` / `allowedStakes()` (shared with the server). Session-goal pay: `sessionGoalReward()`.
- If the same shape of code appears a second time, extract a helper in the right file instead of pasting.

## Adding content (buddies, bosses, gear)
- Append new rows; never reorder or rename ids (saves refer to ids and, for bosses, to list position; secret buddies get `secret_N` from their position).
  Store buddies stay in price order with the Bandit last. Evolved forms must keep the buddy's own face (use its animal, never a bare symbol): the glow, element badge and aura come from `formMarkup`.
- Every buddy and boss is an animal, creature or monster, never an object, plant or weather (`tests/content.test.mjs` checks the picture). Real characters from shows and storybooks (`show`, mythic and legend buddies) may be people, with the emoji that fits the real character (Bluey is a dog, Homer a man). SpongeBob, Patrick and Papaw are the only exceptions (no emoji for their kind).
- Cartoon-cast buddies carry a `show` and use the real characters' names and signature moves. The owner decided to drop the earlier "no real characters" rule: licensing is the owner's call, so say in the PR when a new show is added. There is still no copied artwork or long quotes (emoji only), and only kid-friendly shows (rated for children / PG at most): never adult-rated ones. Their themed gear is bought or earned by collecting the cast (`cartoons`, `headliners` counters). Say so in the PR if a new show raises licensing questions; the owner decides about publishing.
- Every boss in `monstersList` is also a buddy (`bossBuddies`, generated from the list; id `boss_<position>`), won by beating it 3 times in its Alpha form. A new boss needs nothing extra, but boss buddies are placed in packs by element.
- Licensed artwork goes in `art/buddies/<buddy id>.png` (see `art/README.md`; `npm run art` lists the ids). The build embeds it and `applyBuddyArt()` (`08d-buddy-art.js`) swaps it in for the emoji: a buddy's `icon` is then an `<img>`, so never put a buddy's `icon` into plain text, use `emojiOf()` / `.emoji` there. Never draw or generate artwork of licensed characters yourself: it comes from the owner. The one exception is the six folk-tale characters (Arthur, Robin, Alice, Sinbad, Aladdin, Dorothy), who come from public-domain stories and are drawn in the house style (100x100 viewBox, thick dark outlines, flat colours, transparent background) from the stories themselves, never from a film's look.
- Every buddy and boss must look different from every other (`tests/art-generated.test.mjs`): if a new one would share an emoji, draw it by adding a row to `scripts/art/specs.mjs` (species, colour, accessory). Every row needs its own species: never recolour an animal another buddy already uses, add a real, different animal's template in `scripts/art/*2.mjs` (the test checks it) and run `node scripts/make-art.mjs`, which writes `art/buddies/<id>.svg` in the house style. A file without the generated marker is hand-made by the owner and is never overwritten. Licensed characters are never added to the specs (see above).
- Every buddy belongs to exactly one pack (`04b-packs.js`); the Collection Book groups by pack. A new buddy is placed by its show, its id or its emoji; `tests/packs.test.mjs` fails if one lands in the catch-all, so add its emoji or id to the right pack.
- Gear needs a `slot` (see Reuse). A piece with `earn: {key, n, text}` and `cost: 0` is a secret: it is awarded by `checkEarnedGear()` (`08c-earned-gear.js`) and never sold.
- Sizes are asserted in `tests/content.test.mjs` (currently 353 buddies, 55 bosses, 121 gear). Change the test together with the data, and run `npm run sim` if prices change.

## Battles: wild buddies and bosses
- Most battles are against a wild buddy (`13b-wild.js`, numbers in `ECON.wild` / `ECON.sell`); a boss comes after every 5-8 of them. `state.wild.id` is the wild buddy being fought, `''` means a boss. Only bosses count toward `monstersDefeated`, raids, the Alpha buddy rule and the golden vault.
- `getBossInfo()` returns the foe for both; check `.wild` before using boss-only data (`currentMonsterIndex`, weak point, `bossBook`). Pick the next foe with `pickNextFoe()`, never `pickNextBoss()` directly.
- A caught buddy you already own is a spare (`state.spares`); `sellSpare()` / `spareValue()` pay far less than the shop price. Only store and secret buddies appear wild (mythic, ultra and boss buddies keep their own ways).
- Fainted buddies revive only after a boss. Quests that count bosses (`boss`, `flawless`) ignore wild buddies. One free buddy swap per battle (`state.swapUsed`): every way of changing the fighter (team chips, Sanctuary equip, adopting, a caught buddy's Equip Now) must go through `useSwap()`. Only team members can fight (`getTeam()` always includes the fighter; `useSwap()` refuses outsiders; a new buddy joins only if `joinTeamIfRoom()`, otherwise the Sanctuary, adopting and Equip Now ask which team buddy it replaces with `openReplaceModal()`; resting buddies cannot be replaced). When the whole team has fainted everyone is revived. When the fighter faints and a team member can still fight, nothing is replaced automatically: answering waits until the player taps a teammate (`needsSwitch()`, `holdForSwitch()`; the forced switch is not the free swap). A boss with `minLevel` only appears for a strong enough buddy (`bossAvailable()`). Boss and wild attack both grow with level (`bossAtk()`, `wildStats()`).
- Tests start on a boss (`openGame` seeds a save); pass `wildStart: true` for the real start. A test that wins several bosses in a row must set `state.wild.id = ''` and `state.wild.since = 99` so a boss comes next.

## Journey systems (moves, status, roles, map)
- Moves take `ECON.moves.slots` slots per buddy (`equippedMoves()`, saved in `state.moveSet`); a new move marked `optional` is never in the default set. Champions can rematch gyms (`ECON.map.rematch`) and hunt the weekly legend (`24c-legend.js`, `ECON.legend`; `legendPets` are won only that way, a wild fight with `state.wild.legend`). Riley races you to each week's legend on a fixed day (`rileyDay()`); losing the race must stay free and kindly worded. Completing a Dex pack pays once (`ECON.dex`). Catching the golden daily rare sets `state.shinies`.
- Moves (`12c-moves.js`): correct answers charge energy (`ultimateCharge`, 0-3); the Moves sheet spends it. Buddies learn moves by level (`MOVES`). Status effects (`12d-status.js`) change scoring, never whether an answer is right; they are not saved. Roles and held items are in `25b-held.js` (roles come from the element).
- The Map (`24b-map.js`): regions unlock by best buddy level, gyms are trainer battles (never catchable, not counted toward the next boss) and a leader boss; each badge pays once. Use `showStoryModal()` for any story window.
- The Champion's Hall (`24d-champion.js`, `ECON.map.champion`): opens with the sixth badge. It is a gym run (`state.gym.champ`) against Champion Nova's six fixed buddies, one of each type, who may swap mid-fight (`championAfterHit`). Winning it the first time makes you Champion (`state.storySeen.champion`, which rematches and legend hunts need) and pays gems, nets, held items and three earned gear pieces (counter `champion`); later wins pay a little once a day.
- The Buddy Dex is the old Collection Book (`30-collection-book.js`, ids still `book-*`): `markDexSeen()` when a buddy is met. Catch Nets, the flawless bonus and the daily rare are in `ECON.wild` / `ECON.daily`.
- After a new battle system: new saved fields need defaults and a normalizer; run `npm run sim` (energy moves shorten battles: `HITS_PER_BOSS` in the sim).

## Parents (portal, settings, timed challenge)
- A parent has their own account at `/parent` (same page, `isPortal()`; the game never loads there, and `syncNow()` must never upload from it). No email, so no password recovery. Server: `15-parents.js`, `16-challenges.js`; client: `35-parent-portal.js` (child's "link a parent" section and the parent page), `03b-parent-controls.js`, `36-challenge.js`. Limits are in `ECON.parents`.
- Linking: the child's device (PIN-gated Parent Report) makes a one-time code; the parent types it. Every key has one writer (`grant:` child, `plinks:` parent, `ctl:`/`chall:` primary parent, `cprog:` child). The first linked parent is the primary and the only one who can change settings; settings and challenges count only while their writer is still the child's primary link.
- Parents get report numbers only (`kidSummary()`), never the save, the PIN hash or friend names. Reuse `reportParts()` for the report on both sides.
- Settings (`setControls`/`applyControls`): lowest grade band, allowed math types, duels. Every new way to change grade, math types or duels must respect `ctlFloor()`, `allowedOp()` and `duelsLocked()`; easier problems must never go below the floor. The server clamps the cloud save too.
- Timed challenge: the server owns the clock (starts at the child's Start tap) and accepts a claim only in time and not faster than `minSecPerProblem` per answer. The device adds the gems once per challenge id (`state.challengePaid`). Only correct practice answers count (`challengeCorrect()` in `checkAnswer`), never duels, tournaments or the vault. Running out of time costs nothing and is worded kindly.

## Saved state
- Every new field gets a default in `freshState()` (`03-state.js`). Loaded saves go through `normalizeState()`: add a small function to `NORMALIZERS` for clamping or repairs.
  Never trust data from localStorage or the cloud.
- If a field changes shape, bump `SCHEMA_VERSION` and add a `MIGRATIONS` entry. Keep saves small (`ECON.save` limits; `pruneState()` trims history).
- The parent PIN is stored only as a hash (`parentPinHash`). Never store secrets in the save.

## Server (Cloudflare Worker + KV)
- Validate every input (names `NAME_RE`, sizes, lists). Never put client text into a response as HTML. Duel questions allow only `<sub>`/`<sup>`.
- KV is eventually consistent and has no transactions: write each key from one writer only, never read-modify-write shared keys
  (see the layout comment in `20-duels.js`). Give every duel key an expiry. Keep reads per poll to one.
- Answers and scoring for stakes stay on the server. The client is never trusted with money-like results.
- Plain http is redirected to https (not for localhost) and every response carries HSTS; keep `insecureRequest()` working. The site must never load anything over http.
- Every response gets the security headers in `30-router.js`. Do not loosen the CSP to make something work; fix the code.

## Kids first: safety and play
- No chat, no free text shown to other players, no sharing of personal data, no tracking or analytics. Player names only.
- Anything involving other players has a parent switch (`duelsOnline`) and must work when it is off.
- Stakes may only ever be gems, never levels, XP or buddies. Keep a free option. Losing must never go below zero.
- Be kind in copy: a missed day pauses, it never punishes; wrong answers explain how, they do not scold.

## UI rules
- The page runs full screen on iPhones (status bar overlaps it): keep the `env(safe-area-inset-*)` padding on `.game-container`, modal overlays and fixed banners. Test layouts at 375px with wider letters (iPhone text is wider than the test machine's), not just at 360px.
- Every window gets a sticky ✕ (top-right) automatically from `data-close` / `data-esc` (`addCloseButtons()`); never make people scroll to a bottom button to leave. Window height uses `dvh` so iPhone toolbars cannot hide the bottom.
- Phone first: must work at 320x568, 360x640 and 420x800 with no sideways scroll and the main arena visible without scrolling.
- Tap targets 44px minimum (the keypad may be 34px tall on very short screens). Every icon-only button needs `aria-label`.
- Respect reduced motion (`.reduce-motion`, `motionReduced()`); new animations are disabled by that class automatically, new canvas/particle effects must check it.
- Small text needs 4.5:1 contrast. Use the CSS variables in `:root`, not new one-off colours.
- Short iPhones (SE: 375x548 to 647) are the tightest case: decorative rows hide by height in `styles.css` so the equation and answer box never clip. Windows need `min-width:0` and must stay inside the screen with wide letters; `tests/windows.test.mjs` checks both.
- The answer area (`.arena`, `#equation-mount`) is a size container: the equation is sized from the room it has (`cqh`), and banner then feedback step aside when it is short. Add rows above it freely, but run `tests/layout.test.mjs` (worst case at six phone sizes). Battle team chips are `.swap-chip` (`.team-chip` is the tournament picker).
- Look at your change: screenshot at 360x640 and 420x800 before calling UI work done.

## Tests
- `tests/helpers.mjs` has `openGame` (browser wired to the built Worker with real headers), `signUp`, `fakeKV`, `call`.
  `openGame(..., { fast: true })` makes timers 20x shorter. Use `serviceWorkers: 'block'` (already set) because the page is served through test routes.
- Add the failing case first when fixing a bug. Prefer asserting behaviour (state, text, API results) over pixel positions.
- Math generators are covered by `tests/generators.test.mjs`. A new math type must pass it unchanged.

## Git
- Work on the branch you were given. Commit messages: short imperative summary, then the attribution lines the session asks for.
- Do not open a pull request unless asked. Do not force-push. Do not commit `node_modules/`.
- Keep commits focused: one feature or fix, with its tests and the rebuilt `worker.js`.

## Mistakes that already happened (do not repeat)
- A regex-based refactor of open/close functions deleted neighbouring functions (`hubStep`, `setDuelsOnline`) and no test noticed. Refactors of many files must be followed by `npm run lint`; do not edit code with greedy multi-line regexes.
- A stray quote or backtick in the old single-file layout silently blanked the whole game. The new build catches syntax errors; still load the page after changes.
- A shared single "ping" key overwrote an invitation with a result notification. Notifications carry a `kind`; decide what a new kind replaces.
- Canvas emoji (trading cards) were grey silhouettes on iPhone Safari because a gradient was the current fillStyle. Draw every canvas emoji with `fillEmoji()`; `tests/cards.test.mjs` enforces it. Chrome hides this bug, so a green desktop test run is not proof for iOS.
- Test pages must not register the service worker, and timers scaled by `fast` mean `setTimeout`-based waits in tests need generous multipliers.
